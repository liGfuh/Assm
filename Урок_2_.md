5\. Есть три вида стэйтментов:



	-Выполняемые инструкции - сообщают процессору, что нужно делать. Каждая инструкция хранит в себе код операции (опкод) и генерирует одну инструкцию на машинном языке.

	

	-Директивы Assembly - сообщают программе об аспектах компиляции. Они не генерируют инструкции на машинном языке.



	-Макросы - являются простым механизмом вставки кода.





6\. Вот следующие правила написания стэйтмента: 



	[метка] mnemonic \[операнды] \[; комментарий]

&#x09;Мнемоника - это команда которая обозначает конкретную операцию процессора.

&#x09;Операнды - это аргументы или данные, над которыми мнемоника выполняет действие.

10\. Регистры дынных - это четыре 2^n-битных регистра, которые используются для арифметических, логических и других операций. (первые четыре регистра в начальной таблице)





11\. Регистры-указатели 



&#x09;Указатель на инструкцию или команду - 2^n-битный регистры IP хранит смещение адреса следующей команды, которая должны быть выполнена. IP в сочетании с регистром CS предоставляет полный адрес текущей инструкции в сегменте.



&#x09;Указатель на стек - 2^n-битный регистр SP обеспечивает значение смещения в программном стеке. SP в сочетании с регистром SS означает текущее положение данных или адрес в программном стеке.



&#x09;Базовый указатель - 2^n-битный регистр BP используется в основном при передаче параметров в подпрограммы. Адрес в регистре SS объединяется со смещением BP, чтобы получить местоположение параметра BP также можно комбинировать с DI и SI в качестве базового регистра для специальной адресации.





12\. Индексные-регистры - используются в индексировании адресации, и , иногда в операциях сложения/вычитания.



&#x09;Исходный индекс - используется в качестве исходного индекса в строковых операциях.



&#x09;Индекс назначения - используется в качестве индекса назначения в строковых операциях.





13\. Регистр управления - это объединение флагов и инструкций. Многие инструкции включают в себя операции сравнения и математические вычисления, которые способны изменить состояние флагов, а некоторые другие условные инструкции проверяют значение флагов состояния, чтобы перенести поток управления в другое место.





&#x09;Флаг переполнения - указывает на переполнение старшего бита данных.

&#x09;

&#x09;Флаг направления - определяет направление влево или вправо для перемещения или сравнения строковых данных.



&#x09;Флаг прерывания - определяет, будут ли игнорироваться или обрабатываться внешние прерывания.



&#x09;Флаг ловушка - позволяет настроить работу процессора в одношаговом режиме.



&#x09;Флаг знака - показывает знак результата арифметической операции. Этот флаг устанавливается в соответствии со знаком элемента данных после выполнения арифметической операции.



&#x09;Нулевой флаг - указывает результат арифметической операции или операции сравнения. Ненулевой результат сбрасывает нулевой флаг в 0, а нулевой результат устанавливает его равным 1.



&#x09;Вспомогательный флаг переноса - после выполнения арифметической операции содержит перенос от бита 3 до бита 4. Используется для специализированной арифметики. AF устанавливается, когда 1-байтовая арифметическая операция вызывает перенос из бита 3 в бит 4.



&#x09;Флаг равенства - указывает общее количество 1-битов в результате, полученном после выполнения арифметической операции. Чётное число 1-битов сбрасывает PF в 0, а нечётное число 1-битов устанавливает PF равным 1.

&#x09;Флаг переноса - после выполнения арифметической операции содержит перенос 0 или 1 из старшего бита (крайнего слева). Кроме того, хранит содержимое последнего бита операции сдвига или поворота.

14\. Сегментные регистры - это специфические части программы, которые содержат данные, код и стек.



&#x09;Сегмент кода - содержит все команды и инструкции, которые должны быть выполнены. 16-битный регистр сегмента кода или регистр CS хранит начальный адрес сегмента кода.



&#x09;Сегмент данных - содержит данные, константы и рабочие области. 16-битный регистр сегмента данных или регистр DS хранит начальный адрес сегмента данных.



&#x09;Сегмент стека - содержит данные и возвращаемые адреса процедур или подпрограмм. Он представлен в виде структуры данных «Стек». Регистр сегмента стека или регистр SS хранит начальный адрес стека.

17\. Регистровая адресация 

&#x09;В режиме регистровой адресации регистр содержит операнд. В зависимости от инструкции регистр может быть первым операндом, вторым или и тем, и другим сразу. Например:

&#x09;

&#x09;

MOV DX, TAX\_RATE   ; регистр в первом операнде

MOV COUNT, CX    ; регистр во втором операнде

MOV EAX, EBX    ; оба операнда являются регистрами





18\. Прямая (непосредственная) адресация 	

&#x09;Прямой операнд имеет константное значение или выражение. Когда инструкция с двумя операндами использует прямую адресацию, то первый операнд может быть регистром или ячейкой памяти, а второй — непосредственной константой. Первый операнд определяет длину данных. Например:





BYTE\_VALUE  DB  150    ; определение значения типа byte

WORD\_VALUE  DW  300    ; определение значения типа word 

ADD  BYTE\_VALUE, 65    ; добавлен непосредственный операнд 65

MOV  AX, 45H           ; непосредственная константа 45H перемещена в AX





19\. Адресация памяти 

&#x09;Когда в режиме адресации памяти операнды определены, то требуется прямой доступ к основной памяти (обычно к сегменту данных) — этот вариант является медленным. Чтобы обнаружить точное местоположение данных в памяти, нам нужен начальный адрес сегмента, который обычно находится в регистре DS, и значение смещения. Это значение смещения также называется эффективным адресом.



ADD BYTE\_VALUE, DL ; добавляем регистр в ячейку памяти

MOV BX, WORD\_VALUE ; операнд из памяти скопирован в регистр





20\. Адресация прямого смещения 

&#x09;Этот режим адресации использует арифметические операторы для изменения адреса. Например, следующие определения определяют таблицы данных:





BYTE\_TABLE DB  14, 15, 22, 45      ; таблица байтов

WORD\_TABLE DW  134, 345, 564, 123  ; таблица слов





21\. Непрямая адресация памяти 

&#x09;Обычно для этой цели используются базовые регистры EBX, EBP (или BX, BP) и индексные регистры (DI, SI), используемые в квадратных скобках для ссылок на память.





MY\_TABLE TIMES 10 DW 0  ; выделяем 10 слов (2 байта), каждое из которых инициализируем значением 0

MOV EBX, \[MY\_TABLE]     ; помещаем эффективный адрес MY\_TABLE в EBX

MOV \[EBX], 110          ; MY\_TABLE\[0] = 110

ADD EBX, 2              ; EBX = EBX +2

MOV \[EBX], 123          ; MY\_TABLE\[1] = 123
